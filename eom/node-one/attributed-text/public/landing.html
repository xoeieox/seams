Seams · node-one

An end-of-October demonstration node of the Seams attribution protocol. Wire version and live limits: checked below, not asserted.

What this node is

  • An origin for the attribution protocol: it accepts exactly two wire kinds — node-key and session-log — refuses everything else at the gate (fail-closed, never accept-and-map-silently), and appends accepted emits to a hash-chained log whose integrity is verified at load time.
  • Attribution, mechanically: every accepted text keeps the name of whoever deposited it; edits fork versions by base version and word-level attribution survives revision. The state is exportable verbatim via GET /api/export.
  • Self-describing: GET /api/hello echoes the wire version this binary actually speaks, the closed gate kinds, its limits, and its chain-integrity posture. Pin it, and refuse to speak past a skew.
  • Keys that check: an outsider mints a real Ed25519 keypair (key:ed25519:<base64>), signs their emits, and the gateway checks the signature — over the canonical body, against the key embedded in the node_key itself — at the gate, at ingest time. A checked deposit arrives with creator_verified set to true and its key fingerprint, in GET /api/export and GET /api/deposits?node_key=…. An unsigned deposit is still welcome: it is a name-only claim, and it says so (creator_verified: false). A bad signature is refused at the gate (bad_signature) and deposits nothing.
  • Budgeted: reads and writes are rate-limited on the socket peer address only (forwarded headers are attacker-controlled and never read). Published shape — enforced at origin: read 300/1500, ingest 10, edit 10, write-global 80, admin 10 attempts, per 10-minute window. Refusals burn nothing; only successes charge.
  • Loopback by ruling: the server binds a loopback interface; public reach, during the demo window, is Cloudflare Tunnel demo plumbing dialing in — wiring, not architecture. A non-loopback BIND_HOST refuses to boot without the named, operator-acknowledged escape hatch.

What this node is not

  • Not verified by any third party. Signatures are checked by this gateway and nothing more — against the key itself, at ingest, by arithmetic. There is no verifier who vouched for this node, its operator, or any deposit, and no verification ceremony of any kind to pass. A checked signature proves control of a private key at deposit time; it does not prove identity, trust, or permanence.
  • No payments, no compensation flow. Compensation in this demo is none, stated plainly. There is no pricing, no payout rail, nothing to pay and nothing that pays.
  • No vouches, no key ceremony, no consent-fork machinery. Keys are disposable: no KMS, no revocation list, no vouch chain, nobody to ask before you mint one. The consent gate for derivation forks is unbuilt and answers 501 consent_gate_unbuilt — this demo does not exercise consent.
  • Not the production network. The steady-state posture is multi-vendor; the Cloudflare leg is explicitly the month-end demo path with a tracked obligation to move off it (the Switter lesson: a single-vendor kill-switch is not a steady state).
  • No identity claims. Node keys are self-published ed25519 identifiers; the node makes no claim about who operates any key, including its own.

Try it

  • GET /api/hello — what this binary actually speaks.
  • GET /api/export — the whole chain, as it stands.
  • /demo — the human-facing page-and-attribution demo this node also serves: signature-checked deposits carry a ✓ and a key fingerprint; typed names stay visibly claims. (/text and /attributed-text answer the same page.)
  • GET /api/deposits?node_key=… — what one key deposited, with the same verified truth as the export.
  • Emit shape: POST /api/emit with {op:"emit", node_key, kind:"session-log", payload:{text, provenance:{origin:"authored"}}}; replay-safe (same bytes re-ack the original receipt).
